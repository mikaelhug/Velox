Velox vs Docker Desktop

Same Mac, same resource caps, same pinned images, one engine under load at a time. The harness and full methodology live in the repo.

Recorded run · 25 August 2026

Apple M4 Pro, macOS 26.6.2, 8 vCPU / 8 GB each

Velox 1.2.0 against Docker Desktop 4.88.0, measured on the same Mac on the same day. Both engines ran the identical Docker Engine 29.7.2, the same containerd image store, the same docker CLI and the same compose plugin, with only one engine resident at a time — so what these numbers compare is the host around the engine, not the engine. Medians over five order-balanced rounds (three for build and compose). Rows whose run-to-run spread was too wide to call are omitted here and published in full, with their raw values, in the report.

Both engines were also checked functionally and came out level on every probe run: bind mounts, host.docker.internal, TCP, UDP and IPv6 publishing, privileged ports, BuildKit with attestations, and linux/amd64, linux/arm/v7 and linux/386 emulation. Velox adds <name>.velox.local; Docker Desktop supports per-container host-IP publishing, which Velox does not, and ships Kubernetes, Scout, Extensions and its AI tooling, which Velox has no equivalent for.
